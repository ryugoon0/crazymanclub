# GPT 재검토용 프롬프트

아래 내용을 그대로 붙여넣고, 첨부 파일로 `01-design-review.md`(검토 문서 원문)를 함께 올린다.

---

당신은 인디/상용 게임 개발 경험이 풍부한 시니어 게임 디렉터이자 Godot 4 엔진 아키텍트다. 칭찬은 필요 없다. 반박, 누락 지적, 수치 근거 위주로 답하라. 확신 없는 사실은 "확인 필요"로 표시하라.

## 배경

나는 1인 개발자다. 「XENO RECLAIMER」(제노 리클레이머)라는 새 IP의 아이소메트릭 3D 액션 RPG를 만든다. 태그라인은 "Kill. Salvage. Evolve. Reclaim."이다.

핵심 루프: 기지 → 미션 선택 → 외계 생명체 수십~수백 마리 사살 → 자원/장비 획득 → 보스/목표 → 탈출 → 보상 → 무기/신체(Bio Augmentation) 강화 → 상위 난이도 → 반복.

장르: Isometric Action RPG + Twin Stick Shooter + Loot RPG + Mission 기반 진행 + 가벼운 방치 요소. Vampire Survivors류 자동 공격이 아니라 직접 조준·사격하는 손맛이 핵심이다.

장기 목표: PC(Windows/Steam) + 모바일(Android, 이후 iOS), 난이도 5단계(Modifier 방식), 장비 파밍/랜덤 옵션, 계정 단위 장기 성장, 파견(방치), PvE 랭킹, 길드, 시즌, 크로스 세이브, 부분유료화. 실시간 PvP/오픈월드는 후순위.

기술: Godot 4.x 최신 안정판, GDScript 우선, 3D 저폴리 캐릭터 + 3D 환경 + 고정 아이소메트릭 카메라, Stylized Dark Sci-Fi. 로컬 개발 PC는 RTX 3070(8GB). 웹게임 아님.

원칙: Data Driven(Resource 기반 WeaponData/EnemyData 등), Manager/싱글톤 남용 금지, 과설계 금지, 프로토타입은 프리미티브 메시로.

첫 목표(Prototype 0.1)는 단 하나의 질문을 검증하는 것이다: **"수십 마리의 Alien을 직접 총으로 쓸어버리는 것이 재미있는가?"**

## 지금까지의 1차 검토 결론 (다른 AI가 작성. 첨부 문서 참조)

1. 기획 문서의 90%는 라이브 서비스 비전이고 프로토타입 명세(경제 수치, 탄약 유무, 사망/실패 규칙)가 비어 있다.
2. 가장 큰 위험: (a) GDScript + 모바일 + 100~300마리 스웜 성능은 측정 전엔 가정일 뿐, (b) 터치에서 직접 조준은 성립하지 않으므로 "PC/모바일 밸런스 동일"은 "동일 데이터 + 플랫폼별 조준 보정"으로 재정의해야 함, (c) 1인 3D 아트 파이프라인이 최대 시간 흡수원, (d) "Slayer Level / Slayer Corps" 명칭은 참고 원작(Alien Slayer)의 제목 단어라 IP 원칙과 모순.
3. Godot 4 유지. 조건: 프로토타입 첫 주 벤치마크에서 PC 100마리 60FPS. 실패 시 엔진 교체 전에 적 시뮬레이션만 GDExtension(C++)으로.
4. 성장 축이 7개(Character Level, Slayer Level, Bio 6부위, 무기 강화, 랜덤 옵션, 연구, 용병단)라 어느 것도 체감이 안 될 위험. 0.1은 무기 구매/강화 + Bio 3부위(Arms/Legs/Torso)만.
5. 0.1 범위: 캐릭터 1, 그레이박스 맵 1, 무기 3(Assault Rifle/Shotgun/Plasma Rifle), 적 3(Runner/Drone/Tank), 보스 1(Tank 데이터 확장), 웨이브 5 → 보스 → 탈출, Credit 드롭, 상점, 강화, JSON 세이브, 로컬 텔레메트리, 벤치마크 씬. 제외: 스킬 1~4, 우클릭 보조 공격, Character Level, 아이템 드롭/레어리티, Minigun 열 시스템, 모바일 입력.
6. 첫 마일스톤 M0: AR 1종 + Drone 1종 + 스폰 + 사망 + 감각 패스(히트스톱/셰이크/넉백/파편/SFX) + 100마리 벤치마크. 여기서 재미없으면 상점/성장은 재미를 만들어 주지 못한다.
7. 아키텍처 핵심: Autoload 3개(Events/Profile/SaveService)로 제한, 입력을 `InputSource`(move/aim/fire) 추상으로, 모든 강화·랜덤 옵션·난이도 Modifier·Elite 접사를 단일 `StatModifier(stat, op, value)` 체계로, 적끼리 물리 충돌 없음 + 내비게이션 에이전트 없음(조향 + 공간 해시 분리) + AI 틱 분산, 세이브는 `user://`에서 Resource를 load하지 않고 JSON + 스키마 버전 + 계정/캐릭터 분리 + 통화 딕셔너리 + 아이템 def/instance 분리 + RunResult 레코드.
8. 라이선스 주의: Flux.1 dev 비상업, Hunyuan3D 지역 제한 가능성(한국), Mixamo 약관, 순수 AI 생성물의 저작권 불인정, Steam AI 공개 정책. 모두 확인 필요.

## 당신에게 요청하는 것

### 1. 1차 검토 반박
위 8개 결론 중 동의하지 않는 것을 골라 근거를 대라. 특히:
- Godot 4에서 GDScript로 CharacterBody3D 없이 100~300마리를 돌리는 접근이 현실적인가? 더 나은 구조(MultiMesh + 서버 API 직접 호출, GDExtension 즉시 도입, C# 등)가 있는가?
- 0.1에서 스킬/보조 공격을 완전히 빼는 것이 "손맛 검증"에 오히려 불리한가?
- Minigun 대신 Plasma Rifle을 고른 것이 무기 3종 차별화에 최선인가?
- 성장 축을 2개로 줄인 것이 과한 축소인가?

### 2. 결정 요청 항목에 대한 당신의 답과 근거
| # | 질문 | 1차 권장안 |
|---|---|---|
| B | 모바일 조준/발사 방식 | 오른쪽 스틱 밀면 발사 + 데이터 기반 조준 보정. 0.1 미구현 |
| C | 탄약 존재 여부 | 있음(탄창 + 예비탄 + 미션 내 픽업) |
| D | 사망/실패 규칙 | 미션 실패, Credit 50% 보존, Alien Sample 전량 상실. 탈출 성공 시 전량 보존 |
| E | "Slayer" 명칭 | Reclaimer 계열로 교체 |
| G | 테스트 프레임워크 | GdUnit4 |
| H | 기준 Android 기기 | 3~4년 전 미드레인지 1대 지정 |
| J | Slayer Level(엔드게임 무한 성장) 귀속 | 계정 귀속 + 캐릭터별 배분 |
| K | 난이도 명칭 | Normal/Hard/Nightmare/Hell/Abyss 유지 vs 게임 톤에 맞는 고유 명칭 |

### 3. 1차 검토가 놓친 것
- 위험 요소 중 누락된 것
- 프로토타입 0.1에서 검증 가능한데 빠진 시스템
- 반대로 0.1에 아직 남아 있는 불필요한 요소

### 4. 경제 초안
0.1용 수치 초안을 제시하라: 적 종류별 Credit, 미션 클리어 보너스, 무기 3종 가격, 강화 5단계 비용 곡선, Bio 3부위 비용. 목표: 미션 1회 보상으로 첫 강화 1회, 3회 반복으로 두 번째 무기 구매. 10~15분 플레이 기준.

### 5. 무기 3종 감각 스펙
Assault Rifle / Shotgun / Plasma Rifle 각각의 rpm, 피해, 탄창, 재장전, 산탄 각, 반동, 투사체 속도, 히트스톱 길이, 카메라 셰이크 강도 초안. "3개가 확실히 다르게 느껴진다"가 목표.

### 6. 적 3종 + 보스 행동 스펙
Runner/Drone/Tank/Boss의 HP, 속도, 공격, 넉백 저항, 스폰 비율, 그리고 "50마리가 몰려올 때 재미있는 무리 움직임"을 위한 조향 규칙 제안.

### 7. 사실 확인
다음 항목의 2026년 9월 기준 현황을 아는 범위에서 답하고 모르면 "확인 필요"로 남겨라: Godot 최신 안정 버전, Jolt 물리 내장/기본값 여부, Godot .NET의 iOS 지원 상태, Unity 무료 티어 매출 한도, Flux.1 dev/schnell 라이선스, Hunyuan3D 라이선스 지역 제한, Mixamo 상업 이용 약관, 한국의 AI 생성물 저작권 인정 여부, Steam의 AI 콘텐츠 공개 정책, GdUnit4의 최신 Godot 호환.

## 출력 형식
- 항목 번호를 유지하라.
- 각 주장에 "왜"를 한 문장 이상 붙여라.
- 수치는 표로.
- 1차 검토와 의견이 갈리는 곳은 "이견:"으로 시작하는 줄로 명시하라. 이 줄들을 모아 다시 1차 검토자에게 전달할 것이다.
