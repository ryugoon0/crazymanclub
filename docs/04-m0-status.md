## M0-2에 들어간 것
- 히트스톱(프레임 단위, `WeaponData.hit_stop_frames_*`), 카메라 트라우마(사격 0.035, 킬 0.08, 피격 0.35), 피격 플래시/윈드업 스쿼시(셰이더), 넉백(시뮬레이션 임펄스 × (1-저항)), 파편 버스트(MultiMesh, 킬당 7개), 바닥 혈흔(MultiMesh 링 버퍼 400, 12초), 머즐 플래시(라이트 + 가산 빌보드 2프레임), 트레이서
- SFX 8종을 `tools/gen_sfx.py`로 절차 생성(샘플 없음, 라이선스 문제 없음). `AudioPool` 보이스 24, 같은 소리 동시 3, 우선순위 스틸
- Runner(노란 구, 52HP, 7.2m/s, 피해 6)·Tank(보라 박스, 660HP, 2.6m/s, 피해 36) 추가. 스폰 비율 Drone 40 / Runner 50 / Tank 10
- 접선 편향(먼 적은 인덱스 홀짝으로 좌우로 벌어짐), 거리 기반 조향 주기
- 감각 토글: F1 히트스톱, F2 셰이크, F4 넉백, F5 FX(파편/혈흔/머즐/트레이서), F6 오디오, F7 플래시. HUD에 상태 표시
- 카메라 오프셋 (14,20,14) → (10,14,10)

## 컨테이너 측정(2.1GHz Xeon, 렌더 없음, `--bench-fast`)
| 적 수 | sim ms | physics ms(sim 포함) | main ms |
|---|---|---|---|
| 100 | 1.58 | 4.16 | 0.55 |
| 200 | 3.10 | 5.35 | 0.61 |
| 300 | 5.22 | 8.15 | 0.71 |
FX(파편/혈흔) 추가 후에도 sim/physics 비용 변화 없음. FPS 열은 헤드리스 루프 상한이라 무의미.

## 관찰(스크린샷 기준)
- 플레이어가 가만히 있으면 Runner 무리가 4초 안에 도달해 HP가 절반 이하로 떨어진다. 움직이지 않는 플레이어 기준이라 정상. 실제 수치는 플레이테스트에서.
- 접선 편향 후에도 스폰 지점 8곳에서 오는 무리가 줄지어 보인다. 통로/장애물 뭉침은 실플레이 관찰 필요.
- 혈흔 데칼이 크고 둥글다. 텍스처 없는 플레이스홀더. 아트 단계 전까지 유지.

## PC에서 해야 할 것
1. `git fetch origin godot/main && git checkout godot/main`, Godot 4.7.2로 열기(플러그인 활성화 후 재시작 요구 가능)
2. F5 실행 → 마우스/패드로 30초 내 30킬 가능한지, F1/F2/F4~F7 켜고 끄며 어느 쪽이 재미있는지
3. F3 → 벤치마크(약 3.5분) → 콘솔의 `BENCH ...` 6줄과 `GATE ... PASS/FAIL`을 이 리포의 `docs/bench/`에 기록하거나 그대로 붙여 주기
4. 결정 H(테스트 Android 기기 모델), I(Mac 보유) 답
