# M0-1 Gate — 잠정 측정 (Gate 하드웨어 아님)

날짜: 2026-09-19 · Godot 4.7.2 · `res://levels/benchmark.tscn -- --bench-fast --bench-quit`
환경: 원격 컨테이너, Intel Xeon 2.10GHz 4스레드, **GPU 없음 → Mesa llvmpipe 소프트웨어 래스터라이저**, 1280×720, Compatibility(GL) 렌더러, 각 수량 2초 측정.
결정 M의 공식 Gate(RTX 3070, Forward+, 30초 측정)는 **아직 실행되지 않았다.** 아래는 코드 경로 검증용이다.

## 해석
- **GPU 17ms 바닥은 llvmpipe가 1280×720을 CPU로 그리는 비용**이다. 적 10마리에서도 17ms. 실제 GPU에서는 이 열이 1~2ms 수준으로 떨어져야 정상.
- 10 → 300마리에서 GPU 증가분은 +3.5ms(소프트웨어 래스터 기준). MultiMesh 스케일링은 문제 없음. **드로우콜 11~15개**: 적 300마리 = 타입당 1콜.
- 우리 코드의 CPU 비용: sim 3.1ms(200), 5.1ms(300). physics ms는 `_physics_process` 전체(sim 포함 + 스포너 + 플레이어 + Jolt).
- main ms가 23~29ms인 것은 llvmpipe 드라이버가 메인 스레드에서 도는 몫이 섞여 있어서다. 분리 불가.
- 판정: **이 환경에서는 FAIL이지만 Gate 하드웨어가 아니므로 무효.** RTX 3070 + 데스크톱 CPU에서 200마리 60FPS는 sim/physics 합 6ms + 실제 GPU 1~3ms 기준으로 여유가 있을 것으로 예상. **확인 필요**: 실제 측정.

  **철회(2026-09-19).** 요구했던 "측정 후에만"을 실제로 수행한 결과 근거가 없었다. 3070 실측에서 1% low는 525 → 109로 매끄럽게 감소하며 절벽이 없고, 300마리 sim은 tick당 6.29ms로 16.67ms 예산의 38%다. `neighbors()` 호출부는 `max_neighbors = 8` 상한이 있어 적 수에 선형이고 임계점이 없다. `docs/04-m0-status.md`의 "계측 버그 3건" 참조.
